# Security policy

Thanks for helping keep Quantum Dot Games projects safe.

## Reporting a vulnerability

Please use the affected repository's **Security → Report a vulnerability** option when private vulnerability reporting is available. This sends the report privately to the repository maintainers.

If that option is unavailable, use the maintainer contact details listed in the repository or Quantum Dot Games organisation profile. If you cannot find a private contact method, you may open a brief public issue asking for a secure way to report a vulnerability, **without including sensitive details or instructions for exploitation**.

Include enough information to help reproduce and assess the issue, such as affected versions, potential impact, and reproduction steps, but share sensitive material only through a private channel. Do not include personal data, credentials, or secrets unnecessarily.

## What should be reported privately?

Please report issues privately when public disclosure could reasonably expose users, credentials, systems, or data to harm. Ordinary bugs with no meaningful security implications can be reported using the repository's normal GitHub Issues page.

## Handling reports

Reports will be assessed according to their impact and the needs of the affected project. Maintainers may ask follow-up questions, provide a fix, or publish a security advisory where appropriate. No fixed response or resolution time is guaranteed.

We appreciate allowing a reasonable opportunity to investigate and address a vulnerability before publishing sensitive details.

Project-specific security policies, where present, take precedence over this shared guidance.
